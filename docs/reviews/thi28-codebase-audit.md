## Standards and structure

- `CONTRIBUTING.md` already specifies separation of concerns, composition, arrow functions, strict TypeScript, and boundary validation. `.oxlintrc.json` enforces function expressions/arrow callbacks in `src`, no explicit `any`, and no non-null assertions. The baseline `pnpm check` passed 144 unit tests, typecheck, lint, format, and build.
- `src/runtime/scheduler.ts` is 891 lines and combines process checks, file snapshots/receipts, step orchestration, retries, review outcomes, and event persistence. It deserves extraction around those boundaries after the incoming control changes settle. Line count alone is not a defect; preserving state transitions and recovery evidence takes priority over a broad mechanical split.
- `src/runtime/server.ts` is 460 lines and handles setup, agent connections, loops, runs, inspection, SSE, tracker, and static assets. The route bodies should be reviewed and extracted by feature in focused slices. The current strict schemas and localhost host/origin checks are useful safeguards; do not remove them during cleanup.
- Domain schemas use Zod at persisted and network boundaries. Static search found no explicit `any` in `src`; remaining casts in UI event handling should be checked against their runtime parse and narrowed where practical.

## Final combined verification

- On 2026-10-07, the disposable combined candidate passed `pnpm check`: format, lint, types, 172 tests, and production build.
- `pnpm test:e2e` passed all 3 browser journeys. `pnpm test:package` passed clean production-only installation, blank initialization, packaged assets/API and shutdown.
- Scoped unrestricted native receipts in PR #28 show Kiro 2.28 parallel review, selected retry without delay, fresh validation, explicit acceptance, stale acceptance rejection and process-tree cancellation, plus Codex 0.160.0 guidance/recovery/retry. PR #29 separately proves native Codex turn interruption. The final code composition adds UI and cancellation changes without changing Kiro's normal execution protocol.
- Live Linear intake was not exercised because no `LINEAR_API_KEY` was configured in the disposable runtime. The configured tracker fixture covers the intake contract and browser path; this limitation must remain in the release notes.

## Bounded follow-ups

- Split `src/runtime/scheduler.ts` and `src/runtime/server.ts` along stable state and route boundaries in focused PRs. Their size is review debt, not a release blocker by itself.
- Cross-process setup writes, in-flight provider replacement and native Kiro resume are not supported. The current local server serializes setup writes in process and advertises unsupported provider capabilities truthfully.
