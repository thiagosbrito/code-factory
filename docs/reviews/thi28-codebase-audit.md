## Standards and structure

- `CONTRIBUTING.md` already specifies separation of concerns, composition, arrow functions, strict TypeScript, and boundary validation. `.oxlintrc.json` enforces function expressions/arrow callbacks in `src`, no explicit `any`, and no non-null assertions. The baseline `pnpm check` passed 144 unit tests, typecheck, lint, format, and build.
- `src/runtime/scheduler.ts` is 891 lines and combines process checks, file snapshots/receipts, step orchestration, retries, review outcomes, and event persistence. It deserves extraction around those boundaries after the incoming control changes settle. Line count alone is not a defect; preserving state transitions and recovery evidence takes priority over a broad mechanical split.
- `src/runtime/server.ts` is 460 lines and handles setup, agent connections, loops, runs, inspection, SSE, tracker, and static assets. The route bodies should be reviewed and extracted by feature in focused slices. The current strict schemas and localhost host/origin checks are useful safeguards; do not remove them during cleanup.
- Domain schemas use Zod at persisted and network boundaries. Static search found no explicit `any` in `src`; remaining casts in UI event handling should be checked against their runtime parse and narrowed where practical.
